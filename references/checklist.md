# 检查清单

每份稿子交付前跑一遍。检查项从机械到判断排序。

## 机械检查（可搜索）

按下面的模式搜稿子。代码块和引用文字以外的每一处命中都是违规。

| 搜什么 | 违规项 | 修法 |
| --- | --- | --- |
| 缩写形式（'ll、're、n't、it's） | 缩写（规则 4.2） | 写全。 |
| 已经……了、曾……过 | 完成时（规则 3.4） | 改一般过去时或一般现在时。 |
| 正在被、正在 | 进行时被动（规则 3.4、3.5） | 改主动、简单时态。 |
| should、would、may、might、could | 非批准情态动词（规则 3.2） | 见 SKILL.md 的情态动词阶梯。 |
| 「，使得」「，从而使」「，进而」 | 「-ing」式从句当动词（规则 3.5） | 另起一句，给真主语。 |
| 分号 | 分号（规则 8.1） | 拆成两句。 |
| e.g.、i.e.、etc.、等等 | 拉丁缩写（GR-6） | 改「例如」「也就是」，或列出各项。 |
| 简单地、轻松地、无缝地、健壮的、强大的 | 不承载事实的填充词 | 删。 |
| 如果 / 当……时 出现在句子中间 | 条件后置（规则 5.4） | 条件移到句首，加逗号。 |

## 可数检查

1. **句长。** 数每一句的字数。程序性上限 20 词，描述性上限 25 词，注 25 词。
   反引号里的命令、带单位的数字、标识符各算一个词（规则 8.6）。
   中文暂定按字算：程序性 40 字，描述性 50 字。
2. **段落大小。** 一段最多六句（规则 6.6）。
3. **多词名词。** 名词串超过三个词就拆（规则 2.1）。
4. **一句几条指令。** 一条，除非动作同时发生（规则 5.2）。

## 判断检查

5. **分类。** 每段是干净的程序性还是描述性？程序用祈使句，描述绝不用祈使句。
6. **语态。** 任何被动句：施动者真的不明吗，这段是描述性吗？否则改主动（规则 3.6）。
7. **条件位置。** 每个「如果 / 当……时」都在命令之前，带逗号（规则 5.4）。
8. **同义词轮换。** 全文一个概念一个词（规则 1.11、9.4）。扫一遍检查 / 核实 / 确认这组、配置 / 设置这组、运行 / 执行这组。
9. **警告。** 命令或条件在前，风险在后（规则 7.2、7.3）。
10. **完整度。** 量词在，连接词在，不是电报体（规则 4.2）。
11. **不可改动项完好。** 代码、标识符、引用报错、专有名词都没变。

## 报告违规时（检查模式）

每条违规给三项：规则编号、违规原文、合规改写。只引用 SKILL.md 里存在的规则编号。

用户要求「合规」时，报告结尾加这句：
「没有任何工具能保证符合 ASD-STE100。最终判断权在写作者。官方标准在 asd-ste100.org 免费下载。」
